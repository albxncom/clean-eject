# How it works

`CleanEjectCore` is a UI-free Swift module with the volume list, the cleaners, the ejector and the one run path (`TargetRunner`: clean or dry-run a target, then eject a volume when asked); the app target is a thin SwiftUI layer on top, and the `cleaneject` tool (`CleanEjectCLI`, hand-written argument parsing, no packages) is a second front end on the same run path. The volume cleaner refuses anything that is not the root of a mounted volume, and refuses the startup volume and fixed internal disks outright. It walks the volume with `fts(3)` in physical mode (symbolic links are reported, never followed) and never crosses to another device, then removes matches with `unlink(2)` and `rmdir(2)` using the exact bytes the file system returned, with one retry on the precomposed (NFC) form of the name because the ExFAT driver lists names decomposed but deletes only by the stored bytes. It supports a dry run and cooperative cancellation. The walk uses `fts` rather than `FileManager`'s enumerator because Foundation hides `._*` files from every directory listing on macOS, which would make the AppleDouble rule a no-op; deletion bypasses `FileManager` because Foundation re-normalises Unicode file names, which ExFAT does not, so a `._café` sidecar would never be found. The prevention markers are created with `mkdir(2)` and `open(2)` using `O_EXCL | O_NOFOLLOW`, so a symbolic link planted at `.fseventsd` or `.metadata_never_index` is reported, not followed.

Folder targets use the same walk with only the per-folder rules. The refusal list is compared on the `realpath(3)` of the folder, so `/tmp/x` (really `/private/tmp/x`) is refused as well; `URL.standardizedFileURL` and `resolvingSymlinksInPath()` would both strip `/private` again and are not used for that check.

ZIP archives are handled by the tools that ship with macOS, not by zip code of our own: entries are listed with `/usr/bin/unzip -Z1` and `-Z -s` (the archive is passed as standard input and named `/dev/stdin`, because unzip treats `*`, `?`, `[` and `\` in an archive's file name as a pattern) and removed with `/usr/bin/zip -d -nw -@`, the exact entry names on standard input so neither wildcards nor the argument length limit apply. The archive is listed again afterwards; any junk entry still present is reported as a failure rather than trusted to zip's exit status, and an entry name zip cannot address exactly (a leading `/` or `./`, `..`, control characters) is reported without being passed to zip.

The AppleDouble merge is native too: each sidecar is unpacked with `copyfile(3)` `COPYFILE_UNPACK` into a scratch file and only the attributes the original lacks are set with `setxattr(2)`, on volumes whose format stores extended attributes natively (`getattrlist(2)`, `VOL_CAP_INT_EXTENDED_ATTR`). Apple's `dot_clean` was not an option: it discards the sidecar whenever the file already has any extended attribute (every file written on macOS 14 or newer carries `com.apple.provenance`), deletes orphaned sidecars outright, and descends into nested volumes.
